# DSH 原生 AI 分身 · 0.4.0-preview.3

本版本在 Harness 内新增“AI 分身”入口。首次搭建和日常管理共用项目沉淀、分身能力、通道连接、身份与规则四个常驻页面，状态保存在当前 profile 的私有目录。安装不会开启接单或发送消息。

当前支持基于已授权知识的问答、流程/交付草稿、Slack 消息回传、所有者决策通知。整理与蒸馏调用宿主已配置模型；没有配置模型时会明确阻止执行。不会把固定模板或安装成功当作实际完成语义整理。

模型沿用宿主选定的提供方与型号，插件为本次有界处理单独设置推理预算：模型支持时，路由选择 `off` 或 `low`，其他结构化任务选择 `low`；不支持这些档位则保留宿主选择，不修改日常会话的默认设置。路由最多 2048 Token，草稿 6000，整理、蒸馏和检查 12000；单次模型调用最多 90 秒。达到上限或未完整结束时明确失败，保留原采用版，不把部分结果当成通过。

## 安装与打开

要求 Node.js 22.13+、官方 DeepSeek Harness **Web / Desktop 0.2.1-rc.2 / 0.2.1-rc.3**。Desktop 已验证安装启用、真实模型整理蒸馏及本地日报和回流，完整状态见文末；其他宿主版本需重新验证。宿主必须配置可用的真实模型，Slack 则需要本人完成应用授权并提供最小所需权限。已有 Claude 等产品的 Slack 授权不能自动视为本插件已获授权，也不要复制其他产品的会话凭据。

本版 Slack 仅支持用户自有应用的 Bot Token 直连，尚不支持 Claude 云端 Slack 连接器转接。已有获批的 Claude Code 工作流可以继续使用其原有连接，但这与本插件接通 Slack 是两个状态；将组织消息交给另一个运行端或模型处理也必须符合组织的授权范围。

先阅读 README 和 [全部 Releases（含预发布）](https://github.com/oxmumu3/ai-twin-starter/releases)，选择已公开且兼容的版本，核对同一 Release 的 `.tgz` 与 `SHA256SUMS` 后，按 [安装说明](dsh-install.md)安装。先在独立测试 profile 验收，保留旧 profile 与私有状态备份，不把公开 0.3 包当成原生 0.4。下载、安装登记和组件实际启用分别检查；GitHub 预发布不代表官方市场收录。

打开侧栏“AI 分身”。Harness 原有项目、聊天、插件和设置保留；切换分身管理页不会自动继承或执行当前聊天。

## 首次搭建

1. 项目沉淀：从 Harness 已登记工作区明确选择一个项目，新建专用服务会话或明确选择已有会话，填写项目目标和机制。插件在项目内生成 `twin-project/`，含 PROJECT、INDEX、CAPTURE 文档及 context/sop/skills/tools/outputs 目录。已被你手动修改的文档会保留，不覆盖原始项目文件。
2. 盘点项目文件：仅盘点元数据。显式勾选要读取的 Markdown/纯文本来源，再整理。模型产物经来源、行号和文件指纹检查，生成项目概览、材料分类和缺口；未知事实保留为缺口，工具说明不代表工具已可执行。
3. 分身能力：从整理结果生成候选，输入一个具体试跑任务。先检查来源与边界，再生成不外发的真实草稿；查看输出和依据后明确采用。候选不会自动替换当前能力包。
4. 通道连接：在原生凭据配置中保存 Slack Bot Token，再填写工作区、所有者稳定 ID、所有者私聊、允许读取的频道和允许发送的目的地。分别执行只读核验、一次明确的所有者回传测试。测试消息本身也有持久发送记录，未知结果不能重复点击补发。
5. 身份与规则：以平台稳定 sender ID 登记同事或 Agent，限定知识种类/卡片、读取/草稿/回复动作、目的地和有效期。陌生身份默认无权。设置巡检间隔、每轮任务预算、是否逐次审批；复核规则后明确启用。

## 日常使用

日常概览显示待处理、待审批、发送待核查、已发出任务及服务状态。四个基础模块一直可打开；暂停、来源变更、撤权或通道故障不会退回新用户状态或删除历史。

“分身能力”内的“本地日报”接受明确选定的项目内 CSV，显示有效行汇总、异常行数量、正文预览和历史。当前表头为 `date,orders,revenue,cost`，行数、金额与大小限制见 [SETUP](../SETUP.md#本地有界工作流与材料回流)。产物留在项目 outputs 中，不自动发送。

“项目沉淀”内的“材料回流”接受明确选择的 Markdown/纯文本，先提交待采纳，再审阅正文并明确采纳；成为项目来源文件后，还要单独加入选材、重新整理、蒸馏、试跑和采用能力候选。采纳文件不会自动改变当前分身能力。可继续使用兼容 CLI。插件不会监听全部私人聊天或自动把每次交流当成已确认事实。修改目标、机制、来源或授权后，相关能力及任务需要复核；旧能力版本和已发送回执保留。

两项本地工作由当前主人从原生界面显式发起，远程来信不能调用它们。记录跟随当前绑定项目，页面重开后仍可查看；中断操作仅可按原操作编号核对恢复，输入或产物变化会明确停止，不覆盖已有文件。每个项目活动区最多 32 份日报、128 条回流；已完成日报和已采纳材料可明确归档到 `.agent-twin/workbench-archive/`，保留原文件与完整记录，并继续防止旧请求重复生成。未完成或失败的操作不能直接归档，需要先核对恢复。

多范围来信先在授权 scope 清单内做有界路由；路由阶段不接触完整材料或私有卡片。不确定就保留待决策，不能靠消息中的指令扩大范围。执行模型只取得本次身份已授权范围的卡片，不取得整个项目资料包。

Agent/Bot 必须明确登记为 agent/bot 角色并授权稳定 sender ID；未知机器人和分身自身消息不会进入服务，避免循环。

## 消息、审批与恢复

- 仅轮询明确允许的 Slack 入口，在首次明确启用时为全部入口保存新消息基线；保留游标、平台消息去重键、任务和 outbox。暂停后恢复沿用游标，不重新丢弃待处理消息。
- 按服务设置的间隔推进有界批次。普通线程回复只覆盖启用后已观察的新根消息；每次读取一页，在频道和已知线程间轮转。最多跟踪 64 个新根线程；缺线程权限、分页/覆盖不完整或容量不足会显式提示，不能声称扫描过所有历史线程。
- 一次审批绑定任务、输出、来源、身份、规则、账号及目的地。审批不会扩大长期授权；这些条件变化后需重新生成和审批。
- 发送前落盘。进程在发送附近退出时，重启保留未知状态，先查同一平台消息/metadata；未知发送不自动重试，不按正文相似度猜送达。
- 所有者升级通知与业务回复是独立的 outbox 记录。通知只含任务标识和状态，不附整个项目、原问题或私有草稿。
- “内容已生成”“平台报告发出”“对方实际收到/已读”分别记录。Slack 返回消息 ID 不等于真实收件人已读。

## 当前边界

宿主和电脑需持续在线。禁用插件会注销 UI、接口和定时器，并取消进行中的模型/通道调用；持久材料和历史不删除。

本版任务执行器限定为授权知识问答、草稿和正规通道回传；不开放任意 shell、付款、删除或全宿主工具执行。工具卡片描述的是输入、条件和边界，真实外部工具还需独立适配、授权及验收。免打扰时间尚未实现，非空配置会被拒绝，不显示为已生效。

旧 `agent_twin` 工具及 CLI 保持 0.3 兼容行为，其 channel_tick 仍强制 dry run；原生后台服务是另一条明确配置、试跑和启用的执行路径。

## 私有状态与迁移

默认状态目录位于当前 profile 的 `data/agent-twin-native`。原生配置可明确覆盖为绝对目录，禁止自动使用当前工作目录。凭据只通过宿主 secret 字段读取，不写入项目资料、任务或状态快照。

状态使用私有文件权限、原子替换、校验和、revision 和串行锁。损坏数据不会静默清空；活跃或无法确认的锁不会被抢占。恢复时遇到锁冲突请先核对是否有另一个宿主使用同一状态目录，不要手工删除活动锁。

升级前备份当前 profile 私有状态；先停用旧组件再安装新包。接单和真实通道验收在所有者授权的目标上完成，不复用测试台账作为真实服务成绩。

## 此预发布的验收状态

上一预发布已在官方 Web 宿主 0.2.1-rc.2 的独立 profile 安装，实际走通原生四模块：明确绑定零散测试项目、生成沉淀框架、显式选材、整理与蒸馏、具体任务试跑、采用候选、连接核验、身份与规则、明确启用、审批和发送记录。未认证请求被拒绝，外域来源被拒绝。

上述 Web 集成验收使用明确标记的合成模型及隔离消息适配器，用于检查 SDK 调用、界面、权限和状态流转；生产默认使用真实 Slack 适配器，没有内置成功回执或演示资料。

Desktop 0.2.1-rc.2 已通过正式插件界面完成安装、启用与本轮升级，并在专门的合成测试项目中真实调用宿主模型完成整理、蒸馏、逐卡审查、生成草稿和明确采用。最终采用包含 11 张卡，10 张已有来源确认，1 张内容仍待确认、未用于任务；真实检查也曾拒绝超出来源的断言。原生日报正确汇总两行有效数据、列出一行异常；正文与文件一致，归档后原文件保留。材料提交、正文审阅、明确采纳和另行加入来源均已操作；新来源要求重新整理和蒸馏，没有自动替换能力。真实 Slack 收发、更多任务的内容质量、同事体验及长期稳定性尚未完成验收。

自动测试另覆盖来源变更、到期撤权、首次多频道基线、并发锁、进程恢复、消息去重和未知发送不重试。它们不代表真实服务已经上线或连续运行。
