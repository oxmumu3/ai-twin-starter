# 0.4.0-preview.2 发布说明

本预发布把材料整理、分身能力、消息通道和身份规则放进 DeepSeek Harness 的原生工作台，首次搭建完成后可持续管理。它用于试用和验证，尚未完成真实团队生产验收。

## 兼容与安装

- 宿主版本：官方 DeepSeek Harness Web / Desktop 0.2.1-rc.2；Node.js 22.13+。
- Desktop 已实测安装启用、升级、真实模型整理蒸馏及本地工作流；各步骤证据见下文，其他宿主版本需重新验证。
- 阅读 README 与全部 Releases（含预发布），选择实际公开的兼容安装包，验证同一 Release 的 `SHA256SUMS`，安装后回读组件启用状态。不要仅依赖 `/releases/latest`。
- GitHub 预发布是分发渠道，不代表官方市场收录、官方审核或真实服务已上线。

## 本版新增

- 四个常驻模块：项目沉淀、分身能力、通道连接、身份与规则；首次搭建和日常管理共享状态。
- 显式选材、来源校验、模型整理与蒸馏、候选试跑及明确采用；来源变化使受影响内容需要复核。
- 根据稳定平台身份与规则，仅向执行模型提供本次获准的来源卡片，支持知识问答、草稿和授权 Slack 回传。
- 持久任务、审批、outbox、去重、游标、暂停恢复，以及发送结果未知时保留待核查状态。
- 原生“分身能力”新增 CSV 日报、异常提示、正文预览与历史；“项目沉淀”新增材料提交、审阅、明确采纳及独立加入来源。主人显式发起，远程来信不能触发。
- 日报与材料回流有持久操作编号，重启可核对原操作，输入或产物变化时停止；材料采纳不会自动更新能力。兼容 CLI 继续提供，详见 [SETUP](../SETUP.md#本地有界工作流与材料回流)。
- 已完成记录可显式归档，保留原文件、完整记录与旧请求去重信息；自动刷新保留操作失败提示，模型失败返回固定类别，截断或部分结果不会被采用。
- 模型任务按宿主公布的能力选择本次推理强度，修复继承高强度设置后耗尽有界 Token 预算的问题，不更改全局模型设置；切换服务项目后，旧选材弹窗失效，避免将旧项目勾选带入新项目。
- 保留 0.3 通用 CLI / `agent_twin` 工具路径；其 `channel_tick` 仍强制只读 dry-run。

## 已验证

上一预发布已在官方 Web 宿主的独立 profile 安装并操作原生四模块，走通项目绑定、选材、整理、蒸馏、试跑、采用、通道核验、身份规则、启用、审批、发送记录和重启恢复。该端到端路径使用明确标记的合成模型与隔离消息适配器，验证宿主 SDK、界面、权限与状态流转。

本轮最终源码自动测试 245/245 通过，0 失败、0 取消、0 跳过。命令为 `node --test --test-concurrency=1 test/*.test.mjs`；测试文件串行执行，多进程恢复用例内部的 30 轮、每轮 10 个进程及原超时保持不变。测试覆盖来源变更、到期撤权、首次多频道基线、并发锁、恢复、去重、未知发送不重试，以及日报、材料回流、归档、项目隔离和有界模型调用。实际安装包逐文件比对源码，并检查私有运行状态、凭据形态、机器路径和已知业务标识未进入包。

Desktop 通过正式插件界面安装并启用公开 preview.1，再更新 preview.2 包。专门的合成测试项目实际经过本插件 NativeExecutor 调用宿主模型，完成材料整理与卡片蒸馏；后续批次包含明确采纳并加入来源的新材料。真实检查曾拒绝一条超出来源的卡片断言，没有允许采用或开启服务。重新蒸馏后，11 张卡均通过依据检查，10 张已确认卡参与草稿生成，另 1 张候选内容保持待确认；实际草稿保留知识缺口、无 Slack 授权和更新能力需重走流程的边界，随后已在原生界面明确采用。该单次样本不代表所有任务的内容质量均已验证。

原生日报实跑两行有效记录汇总为 7 单、收入 220.70、成本 130.35，并明确排除一行缺值记录；界面正文与实际文件一致。归档后完整记录及原文件保留，更新插件后仍显示归档数量。材料回流完成提交、正文审阅、明确采纳和另行加入选材；新材料不会直接覆盖当前能力。所有数据均为合成验收材料，日报未发送。

## 仍待验收

真实 Slack 收发、更多任务的内容质量、陌生用户首次安装体验、真实同事体验，以及长期无人值守稳定性。Desktop 验收项目尚无 Slack Bot 授权，服务保持关闭；没有向任何同事或本人发送测试消息。合成测试、安装成功、平台返回消息 ID 均不能替代这些结果；平台报告发出也不代表收件人已读。

## 使用边界

原生路径必须连接宿主真实模型和用户自己的 Slack 授权；所有者明确启用前不接单。任务执行器限于授权来源卡片的问答、草稿和消息回传，不执行任意 shell 或全宿主 Agent 工具。工具卡只是说明，真实外部工具仍需单独适配、授权和验收。宿主、电脑、模型和网络可用性共同决定在线状态。

升级前备份私有状态，保留能力历史和发送回执；按宿主流程停用旧组件并安装新版本，先用独立 profile 验收。运行步骤见 [native.md](native.md)。
