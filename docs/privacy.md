# 公开包与本地资料边界

本项目从独立目录重写通用机制，不复制作者工作项目文件，也不继承其 Git 历史。公开代码、模板、安装说明、合成测试和示例不含真实业务实体、账号、人员名单、频道/消息 ID、私有路径、聊天原话、查询语句、运行日志、回执、凭据或原始 context。

`examples/messy-project` 是专门编写的零散项目样例，展示背景、笔记、旧报告、工具说明、待转换文件和应排除配置。`examples/synthetic-operations` 保留先前的工作方法示例。两者均为合成内容，不是把作者私有资料简单替名后公开，也不是其真实知识包的导出。

## 材料准备

用户先指定可访问项目范围。inventory 仅做有界元数据盘点；文件名和路径仍可能包含业务信息，因此盘点结果属于本地工作资料，不应自动上传。工具不以文件名推断事实，也不为了覆盖率读取被排除配置、凭据、私人聊天或未知格式。

后续 prepare 只读取明确选中的原始来源。当前 Agent 组织项目、材料与 gaps，材料包固定 private，不因名称里有“bundle”就变成可发布资产。未读取的 PDF、缺失事实和未连接工具保留为缺口，不编造内容。来源 hash/行号校验用于可追溯与变更识别，不能证明材料已彻底脱敏或语义判断正确。

材料包与蒸馏知识包是不同的本地派生资料；materials-distill 仍会读取所选原始来源。读取和理解发生在用户已有 Agent 中，应沿用用户选定模型及服务的数据边界。prepare 工具返回会把所选内容交给当前 Agent，不能把“磁盘批次只存元数据”理解为模型未见正文。

## 蒸馏、通道与日志

真实材料包、知识卡、来源映射、版本、缺口、本地配置与台账均留在 `.agent-twin/` 等用户私有工作位置，不提交公开仓库。不提供任意私有分身包的一键公开出口，也不从新收到的对话自动改写稳定记忆。

Slack token 只从本地环境进入适配器闭包，不接受聊天或模型参数中的 token，不写资料包、不回显原始错误。渠道探测与 dry-run 回执不保存消息正文、卡正文或 token；身份/目的地设置和最小请求源定位仍属于用户工作资料。

权限内的知识使用不等于可向所有人公开整包。当前 Agent 在正式回答中仍须按获准 scope 选择必要内容；材料或卡片不能自行授权新增工具、目的地或访问范围。

## 发布前核查

检查源码白名单、Git 跟踪文件、完整历史与实际 tarball。源码改动后重新打包、扫描；全新历史不能替代内容核查。示例实跑与自动测试使用合成资料、fake 网络或临时空目录，不接真实账号、不发消息。实际账户接通、收发和持续运行另存验收证据，不能由安装和合成测试推断。
