# 从零散材料开始的四步示例

这个项目完全虚构：一个维修小作坊需要每周库存摘要。源文本、数字、工具和补充回答均从头编写，不含作者的业务材料、账号或私人对话。

`raw/` 故意没有完整知识库：说明在便笺里，历史纠错在旧报告里，工具契约与代码分开，交接“大礼包”缺少判断规则，另外有 CSV 和待确认的旧 PDF。演示会在目标目录生成一个只有无效测试标记的 `.env`，用来检查盘点是否排除隐藏配置，不读取其正文。

## 亲自跑一遍

Node.js 22+，在仓库根目录执行，目标必须是一个不存在的新目录：

```sh
node examples/messy-project/demo.mjs "$PWD/../twin-demo"
```

这段脚本复演当前 Agent 已阅读合成材料后编写的整理和蒸馏提案；它本身没有语义模型。真实使用时由你正在使用的 Agent 读自己的材料、判断分类与缺口、填写提案，不让演示内容替代真实经验。

## 实际产物

1. **准备材料**：`materials-inventory` 只盘点明确范围内的元数据，列出候选、待转换与排除项。Agent 读选四份文本，形成项目简介、分类材料和缺口。工具分为现有本地只读计数、待接入真实库存、待开发自动采购；保存材料包仍为 `distilled:false`。
2. **补齐一个缺口再蒸馏**：第一版明确缺少固定复核顺序。演示引入 `follow-up/owner-answer.txt` 中带醒目标识的虚构回答，重新准备材料；旧 PDF 保留为本次范围外的缺口。再从原始来源生成 knowledge/judgment/workflow/tool 四类卡，保留行号与 hash。
3. **验证可用与失效**：脚本单独运行示例只读工具，得到 counted=20、reserved=3、usable=17；材料准备 API 自身不执行工具。修改一个来源后，材料桥接拒绝继续、受影响知识卡失效；恢复原内容后复核。
4. **连接通道与权限**：此演示没有真实 Slack 账号，不发送消息、不修改库存、不启动调度。按 [通道说明](../../docs/channel.md) 和 [SETUP](../../SETUP.md) 使用自己的授权继续这两步，不能拿本地演示当真实上线证据。

材料版本在目标目录的 `.agent-twin/materials/generations/`，含 `OVERVIEW.md`、`MATERIALS.md`、`GAPS.md`、结构化 packet 和来源 manifest；蒸馏卡在 `.agent-twin/distillation/generations/`；完整复演回执在 `.agent-twin/demo-receipt.json`。这些都是本地私有产物，不能随真实用户项目上传公开仓库。

需要持续维护时，把新的项目背景、实际案例和已验证的工具契约加入自己的原始材料，再按出处更新。安装本包不能代替日常积累、真实工具授权或本人判断。
